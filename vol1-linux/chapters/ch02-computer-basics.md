# 第 2 章 计算机基本结构与 Linux 基本原理

> 第 1 章我们把机器装好了、开了、验了货。在动手跑命令之前，有必要先搞清楚：这台机器在底层长什么样？Linux 操作系统又是怎么管理硬件、运行程序、处理文件的？这些原理不是为了考试，而是为了让你排障时能从"现象"追溯到"本质"——比如"为什么内存满了系统会卡"、"为什么删除文件后磁盘空间没释放"、"为什么同一个命令在两台机器上行为不一样"。带着这些问题看完本章，后面每一章都会更好懂。

> **本章目标**
> - 能画出计算机五大部件及其协作关系，说清 CPU、内存、存储、I/O 设备各自的角色。
> - 能解释"程序从磁盘到运行"的完整过程：编译、加载、系统调用、进程调度。
> - 能理解 Linux 中"一切皆文件"的含义，说清文件系统树、inode、挂载点的关系。
> - 能区分用户态与内核态，理解系统调用是程序请求内核服务的唯一通道。
> - 对图中出现的关键概念（寄存器、缓存、页表、缓冲区、进程状态等）建立直觉。

## 2.1 计算机的五大部件

现代计算机的基础架构源于冯·诺依曼（John von Neumann）在 1945 年提出的设计：**程序存储原理**——指令和数据都存储在同一块存储器里，CPU 按顺序取出指令并执行。计算机由五大部件组成：

| 部件 | 英文 | 核心职责 | 生活类比 |
|------|------|----------|----------|
| 运算器 | ALU | 执行算术和逻辑运算（加减、比较、位运算） | 大脑的计算部分 |
| 控制器 | CU | 从内存取指令，译码，向各部件发出控制信号 | 大脑的指挥中枢 |
| 存储器 | Memory | 存储程序和数据（分主存/辅存） | 大脑的记忆 |
| 输入设备 | Input | 将外部数据和指令输入计算机 | 眼睛、耳朵、手 |
| 输出设备 | Output | 将计算结果呈现给外部 | 嘴巴、手、屏幕 |

运算器 + 控制器合称为 **CPU（中央处理器）**，是计算机的"大脑"；存储器分为 **主存（内存、RAM）** 和 **辅存（硬盘、SSD）**，前者速度快但断电丢失，后者速度慢但断电保留。

![计算机五大部件及数据流向示意图](/vol1-linux/assets/ch02/01-five-components.png)

*图 2-1　冯·诺依曼架构：五大部件及其协作关系（需配图：左侧输入设备、右侧输出设备，中间 CPU 与内存双向连接，总线贯穿全部）*

**关键结论**：所有程序最终都要被装入内存，由 CPU 逐条取指执行。输入设备负责把数据搬进来，输出设备负责把结果搬出去，存储器负责记住一切。

## 2.2 CPU 与内存：指令如何执行

CPU 内部不是一个整体，而是由若干关键寄存器和单元组成：

| 组件 | 作用 |
|------|------|
| **PC（程序计数器）** | 存放下一条指令的内存地址，执行一条自动加 1 |
| **IR（指令寄存器）** | 存放当前正在执行的指令 |
| **通用寄存器** | 存放运算过程中的中间数据（如 eax、ebx 等） |
| **标志寄存器** | 记录运算结果的状态（零标志、进位标志等） |
| **控制单元** | 解码指令，向 ALU 和内存发控制信号 |

**指令周期（Instruction Cycle）**：
1. **取指（Fetch）**：根据 PC 的地址，从内存取出指令放入 IR
2. **译码（Decode）**：控制单元识别这条指令要做什么
3. **执行（Execute）**：ALU 执行运算，或访问内存，或与 I/O 设备交互
4. **访存（Memory Access）**：如有需要，读写内存
5. **写回（Write Back）**：将结果写回寄存器或内存

![CPU 内部结构与指令周期](/vol1-linux/assets/ch02/02-cpu-internal.png)

*图 2-2　CPU 内部关键寄存器与指令周期流程（需配图：PC→内存→IR→控制单元→ALU→寄存器，形成闭环）*

**为什么关心这些？** 当你写 `for i in {1..1000000}` 时，CPU 实际上在循环地执行"取指→译码→执行"。理解这一点，能帮你理解后面章节里"上下文切换""缓存失效""分支预测"等性能概念。

## 2.3 存储层次结构

计算机的存储不是一块均匀的空间，而是一个**层次金字塔**：越靠顶越快越贵越小，越靠底越慢越便宜越大。

```
        寄存器 (Registers)      ~ 纳秒级，几十～几百字节
           │
        一级缓存 (L1 Cache)      ~ 纳秒级，几十～几百 KB
           │
        二级缓存 (L2 Cache)      ~ 几纳秒，几百 KB～几 MB
           │
        三级缓存 (L3 Cache)      ~ 十几纳秒，几 MB～几十 MB
           │
        主内存 (RAM / DRAM)      ~ 百纳秒级，几 GB～几百 GB
           │
        固态硬盘 (SSD / NVMe)    ~ 微秒级，几百 GB～几 TB
           │
        机械硬盘 (HDD)           ~ 毫秒级，几 TB～几十 TB
           │
        网络存储 / 磁带          ~ 毫秒～秒级，无限扩展
```

![存储层次金字塔](/vol1-linux/assets/ch02/03-memory-hierarchy.png)

*图 2-3　存储层次结构：从寄存器到网络存储，速度与容量呈反比（需配图：金字塔形，顶部最小最快，底部最大最慢）*

**局部性原理（Locality）**：程序访问数据具有"时间局部性"（刚用过的很快再用）和"空间局部性"（刚用过的附近很快再用）。CPU 利用这个特性，把最近用到的数据缓存在 L1/L2/L3 缓存里，避免每次都去慢速的内存甚至硬盘取数据。

**虚拟内存**：每个进程看到的内存地址是"虚拟地址"，由操作系统和硬件 MMU（内存管理单元）映射到真实的物理内存。这样每个进程都觉得自己拥有一块连续的大内存，实际物理内存可能是零散的。

## 2.4 I/O 设备与总线

外部设备（键盘、鼠标、网卡、硬盘、显卡）不能直接和 CPU 对线，它们通过**总线（Bus）**与 CPU、内存通信：

| 总线类型 | 作用 | 典型设备 |
|----------|------|----------|
| 系统总线 | 连接 CPU、内存、北桥 | 内存、AGP 显卡（旧） |
| 扩展总线 | 连接外部设备 | USB、PCIe、SATA、NVMe |
| I/O 总线 | 连接慢速外设 | 键盘、鼠标、串口 |

设备通过**中断（Interrupt）**告知 CPU"我有数据了"或"我做完了"，CPU 暂停当前工作去处理设备请求。对于大量数据传输（如硬盘读取），使用 **DMA（直接内存访问）**，让设备直接读写内存，绕过 CPU，提高效率。

![I/O 总线与中断机制](/vol1-linux/assets/ch02/04-io-bus.png)

*图 2-4　I/O 设备通过总线连接 CPU 和内存，中断与 DMA 机制（需配图：CPU、内存、桥芯片、各种 I/O 设备，中断线和 DMA 路径标注）*

## 2.5 Linux 基本原理：从硬件到操作系统

操作系统位于硬件和应用程序之间，是管理计算机资源的主管软件。Linux 作为一类类 Unix 操作系统，其内核负责最核心的资源管理。

Linux 系统通常分为四层（从下往上）：

```
┌─────────────────────────────────────┐
│   用户层：Shell、浏览器、编辑器等应用 │
├─────────────────────────────────────┤
│   系统调用接口：open/read/write/... │
├─────────────────────────────────────┤
│   内核层：进程调度、内存管理、文件系统、驱动 │
├─────────────────────────────────────┤
│   硬件层：CPU、内存、磁盘、网卡等      │
└─────────────────────────────────────┘
```

![Linux 系统架构分层](/vol1-linux/assets/ch02/05-linux-layers.png)

*图 2-5　Linux 系统四层架构：应用 → 系统调用 → 内核 → 硬件（需配图：分层方块图，箭头表示调用方向）*

### 用户态 vs 内核态

出于安全和稳定性考虑，CPU 运行在两种不同的**模式（Mode）**中：

- **用户态（User Mode）**：普通应用程序运行在此模式，只能访问受限的指令和内存，不能直接操作硬件。若想做敏感操作（如写磁盘、发网络包），必须通过**系统调用**请求内核代劳。
- **内核态（Kernel Mode）**：操作系统内核运行在此模式，拥有完全的硬件控制权，可以执行特权指令。

从用户态切换到内核态需要经过系统调用，这个切换有开销（涉及寄存器保存、页表切换等），所以频繁的系统调用会影响性能。

## 2.6 系统调用：程序与内核的桥梁

程序无法直接操作硬件，所有对硬件资源的请求都必须通过**系统调用（System Call）**交给内核。常见的系统调用包括：

| 系统调用 | 作用 | 示例场景 |
|----------|------|----------|
| `open` | 打开文件 | `cat file.txt` 先打开文件 |
| `read` | 读取数据 | 从文件或网络读内容 |
| `write` | 写入数据 | `echo` 输出到屏幕或文件 |
| `close` | 关闭文件 | 使用完文件后释放资源 |
| `fork` | 创建子进程 | Shell 运行外部命令时 |
| `exec` | 执行新程序 | 子进程把自身替换成新程序 |
| `exit` | 退出进程 | 命令执行完毕退出 |
| `brk`/`mmap` | 申请内存 | 程序启动时分配堆内存 |

![系统调用执行流程](/vol1-linux/assets/ch02/06-syscall-flow.png)

*图 2-6　系统调用执行流程：用户态程序 → 陷入内核 → 内核处理 → 返回结果（需配图：时序图，显示用户程序触发中断、CPU 切换到内核态、内核执行、返回用户态）*

**例子**：当你在终端敲 `ls` 时：
1. Shell 调用 `fork()` 创建子进程
2. 子进程调用 `execve("/bin/ls", ...)` 把自身替换成 `ls` 程序
3. `ls` 内部调用 `opendir()` → 系统调用 `getdents()` 读取目录
4. `ls` 调用 `write()` → 系统调用把结果输出到终端
5. `ls` 调用 `exit()` 退出

## 2.7 文件系统：一切皆文件

Linux 继承了 Unix 的设计哲学：**一切皆文件（Everything is a file）**。不仅普通文档、图片是文件，硬盘、键盘、网卡、鼠标、甚至内核内部的某些状态，在 Linux 里都被抽象为文件，可以用统一的 `open/read/write/close` 操作。

### 文件系统树

Linux 只有一个根目录 `/`，所有设备和分区都挂载在这个树下：

```
/
├── bin/        常用命令（ls, cp, mv...）
├── boot/       启动相关文件（内核、引导程序）
├── dev/        设备文件（硬盘、光驱、终端等）
├── etc/        系统配置文件
├── home/       普通用户家目录
├── lib/        系统库文件
├── media/      可移动媒体挂载点（U盘、光盘）
├── mnt/        临时挂载点
├── opt/        可选安装软件包
├── root/       root 用户家目录
├── run/        运行时数据
├── sbin/       系统管理命令
├── srv/        服务数据（网站根目录等）
├── tmp/        临时文件
├── usr/        用户程序和库（usr/bin, usr/lib...）
└── var/        可变数据（日志、缓存、邮件队列）
```

![Linux 文件系统树](/vol1-linux/assets/ch02/07-filesystem-tree.png)

*图 2-7　Linux 根文件系统目录树（需配图：树状图，/ 为根，各子目录作为分支）*

### inode 与文件

每个文件在文件系统里有两个关键概念：

- **文件名**：人类可读的标识，存储在目录项里
- **inode（索引节点）**：文件的元数据（大小、权限、时间、数据块位置等），有一个唯一编号

一个文件可以有多个文件名指向同一个 inode（这就是**硬链接**）。目录本身也是一个文件，它的内容是"文件名 → inode 编号"的映射表。

### 挂载（Mount）

Linux 把不同分区、不同设备（U盘、网络共享、光盘）挂载到文件系统树的某个目录下。比如把一个新硬盘挂载到 `/data`，访问 `/data` 下的文件就是访问那个硬盘。这就是第 1 章里"系统盘 + 持久盘"双盘结构的实现原理。

## 2.8 进程与调度

### 什么是进程

**进程（Process）**是正在执行的程序实例。程序是静止的文件（在硬盘上），进程是动态的（在内存中运行，占用 CPU、内存、文件句柄等资源）。每个进程有唯一的 **PID（进程 ID）**。

Linux 内核为每个进程维护一个 **PCB（进程控制块）**，记录：
- PID、PPID（父进程 ID）
- 进程状态（就绪、运行、阻塞、僵死等）
- CPU 寄存器状态（切换进程时保存现场）
- 内存地址空间、打开的文件列表、信号处理方式

![进程状态转换图](/vol1-linux/assets/ch02/08-process-states.png)

*图 2-8　进程状态转换：新建→就绪→运行→阻塞→终止（需配图：状态机，圆圈表示状态，箭头表示事件触发的转换）*

### 进程状态

| 状态 | 含义 |
|------|------|
| 就绪（Ready） | 已准备好，等待 CPU 调度 |
| 运行（Running） | 正在 CPU 上执行 |
| 阻塞（Blocked） | 等待某个事件（I/O 完成、信号等），不占用 CPU |
| 终止（Terminated） | 执行完毕，等待父进程回收 |

### 调度器

Linux 内核有一个**进程调度器**，决定哪个进程什么时候在 CPU 上跑、跑多久。现代 Linux 使用 **CFS（完全公平调度器）**，试图让每个进程公平地分到 CPU 时间。当一个进程的时间片用完，或发生更高优先级的事件，调度器就会发生**上下文切换（Context Switch）**：保存当前进程的寄存器状态，加载下一个进程的状态，然后继续执行。

## 2.9 Shell：用户与内核的桥梁

**Shell** 是用户与操作系统内核交互的命令行界面。它不是内核的一部分，而是一个普通的用户态程序。常见的 Shell 有 bash、zsh、sh 等（本书默认 bash）。

Shell 的工作循环：

1. **读取**：显示提示符，等待用户输入命令
2. **解析**：把命令行拆成程序名和参数，处理通配符、变量、管道、重定向
3. **执行**：`fork()` 子进程，`exec()` 加载程序，等待执行完毕
4. **输出**：把程序的输出显示在终端，回到步骤 1

![Shell 命令处理循环](/vol1-linux/assets/ch02/09-shell-loop.png)

*图 2-9　Shell 处理一条命令的完整循环（需配图：读取→解析→fork/exec→等待→输出，循环箭头）*

**管道（Pipe）**：Shell 最强大的特性之一。`cmd1 | cmd2` 把 `cmd1` 的标准输出直接接到 `cmd2` 的标准输入，无需中间临时文件。这是 Unix 哲学"每个程序做好一件事，程序间通过文本流协作"的体现。

## 2.10 图解汇总：敲下 `ls` 回车后发生了什么

把本章所有概念串起来，看一个具体例子：你在 Shell 里敲 `ls` 并按下回车，到底发生了什么？

```
你敲 "ls" + 回车
        │
        ▼
┌─────────────────┐
│   Shell (bash)  │  读取输入，解析为命令名 "ls"
└─────────┬───────┘
          │ fork() 创建子进程
          ▼
┌─────────────────┐
│  子进程 (ls)    │  execve("/bin/ls")，把自身替换成 ls 程序
└─────────┬───────┘
          │ 系统调用：getdents() 读取目录
          ▼
┌─────────────────┐
│   Linux 内核    │  处理系统调用，访问文件系统，可能触发磁盘 I/O
└─────────┬───────┘
          │ 通过总线/DMA 与磁盘控制器交互
          ▼
┌─────────────────┐
│    硬件层       │  磁盘读取目录数据，经内存缓存返回内核
└─────────┬───────┘
          │ 结果返回，沿原路返回
          ▼
┌─────────────────┐
│   终端显示      │  把 ls 的输出打印在屏幕上
└─────────────────┘
```

## 本章小结

本章建立了计算机和 Linux 运行的底层认知，五件事：

1. **五大部件**：运算器、控制器（合称 CPU）、存储器、输入设备、输出设备，通过总线协作。
2. **指令执行**：CPU 按"取指→译码→执行"循环工作，寄存器是最快的存储。
3. **存储层次**：寄存器→缓存→内存→硬盘→网络存储，速度与容量反比，利用局部性原理提升性能。
4. **Linux 架构**：用户态程序通过系统调用请求内核服务，内核管理 CPU、内存、文件、设备等硬件资源。
5. **核心抽象**：一切皆文件、文件系统树（根 /）、进程（PID+状态）、Shell（用户与内核的桥梁）。

带着这些原理，再回头看第 1 章的 VMware 虚拟机和第 4 章开始的命令操作，你会明白：虚拟机本质上是软件模拟的一台完整计算机，而你敲的每条命令，最终都会经过 Shell→系统调用→内核→硬件这条链路执行。

## 动手练习

1. 在你的 Ubuntu 虚拟机里执行以下命令，并把输出贴进笔记本：
   - `uname -a`：确认内核版本和架构（x86_64 还是其他）
   - `lscpu`：查看 CPU 核心数、线程数、缓存大小（对应 2.2 节的 CPU 结构）
   - `free -h`：查看内存总量和可用量（对应 2.3 节的主存）
   - `df -h`：查看各分区挂载情况（对应 2.7 节的文件系统树和挂载）
   - `ls -l /dev/sda /dev/null /dev/tty`：观察设备文件（对应 2.4 节的 I/O 设备抽象）
   - `ps aux | head -20`：查看运行中的进程及其 PID、状态（对应 2.8 节）
