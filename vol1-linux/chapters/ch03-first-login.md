# 第 3 章 首次登录：SSH、终端与第一组命令

> 第 1 章我们把机器开了、货也验了。这一章真正"登堂入室"：连上你的云电脑，认识那个传说中的第一个坐标——提示符 `root@book:~#`，跑人生第一组 Linux 命令，然后学会正确地离开（退出、暂停、以及最吓人的"删除"）。学完这一章，你就正式成为一名"服务器使用者"了——剩下的十四章，都是在这块地基上盖楼。

> **本章目标**
> - 能用 `instabox ssh book` 建立连接、正确处理首次连接的指纹确认，并逐段拆解提示符 `root@book:~#` 每一部分的含义。
> - 能熟练执行第一组命令（`whoami`、`id`、`pwd`、`ls`、`hostname`、`uptime`），读懂 `uname -a` 的每个字段，说清"退出、断开、暂停、删除"四种状态的区别。
> - 能理解 `/data/home` 持久盘与 16 GiB 系统盘的分工，记住并执行云电脑使用的三条铁律。

---

## 2.1 建立连接：`instabox ssh book` 与指纹确认

先认识个将在全书反复出场的词：**SSH（Secure Shell，安全外壳协议）**——一种加密的远程登录协议。你以后工作的日常就是"在自己的笔记本上打开终端，SSH 到机房/云端的一台 Linux，然后全程在那边操作"。你在终端里敲的每条命令，都经过加密通道发给远端机器执行，执行结果再加密传回来。市面上所有"连服务器"的方式（`ssh user@服务器IP`、跳板机、各种客户端），底层都是它。

在本书的环境里，连接方式被平台简化到极致：

```bash
instabox ssh book
```

参数解释：`ssh` 子命令让 CLI 帮你完成认证和加密通道，`book` 是目标机器的名字（第 1 章创建的）。平台在幕后处理了密钥和认证，所以**不需要你背服务器 IP、不需要密码、不需要手动配密钥**——这在未来你租 VPS 时要自己伺候的东西，现在平台全包了。

第一次连接，几乎一定会遇到一段"拦路问话"：

```text
The authenticity of host 'book' can't be established.
ED25519 key fingerprint is SHA256:KqIcbT0eET1D0m3kjXxYvN3nR8s9Wq2mF5oG7hJ4lPk.
Are you sure you want to continue connecting (yes/no/[fingerprint])?
```

这段话必须逐字看懂，不许闭眼回车：

| 行 | 意思 |
| --- | --- |
| `The authenticity of host 'book' can't be established.` | 你的电脑**第一次**见到这台叫 `book` 的主机，没法确认它是它自己（可能是冒充的） |
| `ED25519 key fingerprint is SHA256:...` | 主机出示的"身份证指纹"——ED25519 是密钥算法，SHA256 那串是密钥的指纹 |
| `Are you sure you want to continue connecting (yes/no/[fingerprint])?` | 要你确认：见过这张身份证吗？ |

**正确答案：在你确信网络环境可信（家里的网、公司的网）的前提下，输入完整的 `yes` 回车**（只输入 `y` 无效，这是 SSH 防呆的设计）。随后你会看到 `Warning: Permanently added 'book' (ED25519) to the list of known hosts.`——你的电脑把这张"身份证"记进了小本本（`~/.ssh/known_hosts` 文件），**下次再见 `book`，它会自动核对指纹，不再询问**。接着出现登录画面，你就进来了。

`yes/no/[fingerprint]` 里的第三个选项是进阶用法：你可以直接粘贴"官方渠道公布的真指纹"，SSH 帮你当场比对。本书按简化流程输入 `yes` 即可，指纹体系的完整原理（含中间人攻击是怎么回事）见第 12 章《网络配置与远程管理》。

> **SRE 贴士**：生产环境里，`known_hosts` 的变化是**高危信号**——如果你连了三年的服务器突然又问你指纹确认，两种可能：机器被重装了（合理），或者有人在中途冒充它（中间人攻击）。资深运维看到陌生指纹警告会立刻停手核实，而不是习惯性 `yes`。**指纹即身份**，这个意识从第 3 章开始建立。

> **生产 vs 实验室**：实验室里对 `yes` 警告可以放松——你的网络是你家的Wi-Fi，对面是平台的机器。生产上每一步都要较真：指纹从哪个渠道拿到的、跳板机的密钥谁在管、连接记录有没有留。同样一个 `yes`，环境不同，代价不同。

## 2.2 认识你的提示符：`root@book:~#` 逐段拆解

连接成功后，你面对的是全书出现频率最高的一行字符：

```text
root@book:~#
```

它看起来像装饰，其实是一块仪表盘。逐段拆：

| 片段 | 名称 | 含义 | 本例 |
| --- | --- | --- | --- |
| `root` | 当前登录用户 | **你现在是谁** | `root`，系统管理员 |
| `@` | 分隔符 | 就是"在……上"的"在" | — |
| `book` | 主机名（hostname） | **你在哪台机器上** | 你第 1 章给机器起的名字 |
| `:` | 分隔符 | — | — |
| `~` | 当前工作目录（current directory） | **你现在站在文件系统的哪个位置** | 波浪号代表"当前用户的家目录"。root 的家目录是 `/root` |
| `#` | 身份标记 | 命令没输完时的提示 | `#` 表示当前是 root（管理员）；如果是普通用户，这里是 `$` |

两个要点刻进脑子：

**第一，`#` 和 `$` 的区别就是权限的区别。** 见到 `#`，你说的话是"圣旨"，文件随便删；见到 `$，你只是个普通用户，动系统文件得先提权。本书全程用 root 演示，所以全程是 `#`——但请每次看到它都在心里念一遍"我现在是 root，手下留情"，第 6 章《用户、群组与权限》我们会创建普通用户 `bookuser`，到时候你会见到 `$`。

**第二，`~` 不是装饰，是路径。** 它等价于 `/root`（root 的家目录）。你敲 `cd ~` 回家、在命令里写 `~/notes`，用的都是它。家目录为什么在系统盘而不是持久盘？2.7 节专门讲，那里有个初学者最疼的坑。

最后一条约定：**书里所有输出块里不会出现这个提示符**，你复制命令时可别把它一起复制了——新手最经典的报错 `bash: root@book:~#: command not found`，就是把提示符当成命令的一部分粘了进去。提示符是机器给你看的，不是机器让你念的。

## 2.3 第一组命令：和你的机器互相认识

现在跑六条命令。每条都按老规矩：说人话、语法、输出、坑。建议边看边敲，敲完把六条的输出一起贴进你的命令笔记本（第 0 章立的规矩，从今天开始执行）。

### 2.3.1 whoami：我是谁

```bash
whoami
```

```text
root
```

最直白的一条：报告**当前登录用户的名字**。输出 `root` 说明你确实以管理员身份登进来了。语法简单到没有参数（它是极少数"光杆命令"之一）。它的价值不在功能，在**印证**——提示符说你是 root，`whoami` 亲口承认，仪器对账。

### 2.3.2 id：我是谁（身份证版）

```bash
id
```

```text
uid=0(root) gid=0(root) groups=0(root)
```

`whoami` 只报名字，`id`（identity）报全套身份：`uid`（User ID，用户编号）是 0——Linux 内部认的是数字，root 永远是 0 号；`gid`（Group ID，群组编号）也是 0；`groups` 说明你属于哪些群组，这里是 root 群组。为什么 `whoami` 和 `id` 要看两遍？因为**提示符可以改、`$USER` 环境变量可以改，唯独 uid=0 这个事实改不了**——确认"我到底是不是真的 root"，以 `id` 为准。群组体系的完整故事见第 6 章《用户、群组与权限》。

### 2.3.3 pwd：我现在在哪

```bash
pwd
```

```text
/root
```

`pwd`（print working directory，打印工作目录）报告你当前站在文件系统的哪个位置。刚登录时你在 `/root`——正好印证了 2.2 节说的 `~` 就是 `/root`。这条命令初学时可派上大用场：文件找不着了、脚本写错位置了，先 `pwd` 看看自己站在哪，八成能找到方向。

### 2.3.4 ls：这袋里都装了啥

```bash
ls
```

刚装好的机器，这条命令很可能什么也不输出——因为 root 的家目录里，肉眼可见的文件一个都没有（默认配置文件都是"点开头"的隐藏文件，第 4 章用 `ls -a` 放它们出来）。

`ls`（list）列出当前目录的内容。语法是 `ls [选项] [对象]`，现在只要记住它默认"列当前目录"，第 4 章我们会把 `-l`（详细格式）、`-a`（显示隐藏文件）、`-h`（人类可读大小）这些参数一个个解锁。这里先埋个直觉：**不输出也是一种输出**——目录空、或者文件都藏起来了，`ls` 都会安安静静。

### 2.3.5 hostname：这台机器叫什么

```bash
hostname
```

```text
book
```

报告主机名，正好是第 1 章 `--name book` 起的那个。这条命令是提示符第二段的"对账口"：提示符写着 `book`，`hostname` 亲口承认。改主机名的正经方法（`hostnamectl`）见第 12 章《网络配置与远程管理》。

### 2.3.6 uptime：机器开机多久了，累不累

```bash
uptime
```

```text
 09:42:10 up 12 min,  1 user,  load average: 0.00, 0.03, 0.05
```

一段话把机器的"入职档案"说完，从左到右：

| 片段 | 含义 |
| --- | --- |
| `09:42:10` | 当前系统时间 |
| `up 12 min` | 已连续运行 12 分钟（你第 1 章创建后开机至今；如果执行过 resume，这里反映的是恢复后的运行时长，具体以你的机器为准） |
| `1 user` | 当前登录的用户会话数（就是你自己；开第二个终端就变 2） |
| `load average: 0.00, 0.03, 0.05` | 过去 1 分钟、5 分钟、15 分钟的平均负载 |

最后那个 load average（平均负载）是运维界的黑话重灾区，一句话先记住结论：**它是"有多少任务在排队等 CPU"的近似值**，和 CPU 使用率不是一回事；4 核的机器上，负载长期在 4 以下算正常，贴着或超过 4 才该紧张。深读它（含"load 高但 CPU 闲是什么原因"这种面试题）是第 9 章《进程管理与系统监控》的内容，现在你只需知道：**开机体检、例行巡检，第一眼都看它。**

至此，六条命令串成了你的"第一条自我介绍"，建议抄成便签贴在显示器边：

```bash
whoami; id; hostname; pwd; uptime
```

`;` 是命令分隔符，一行挨个执行，一次出全套报告。这是你人生中第一条"小流水账"，也是巡检脚本的雏形（第 14 章《Shell 脚本入门》会把它升级成正经脚本）。

> **SRE 贴士**：接手任何一台陌生机器的第一个五分钟，照着这六条跑一遍：`whoami`/`id` 知道自己在替谁干活（有没有权限）、`hostname`/`pwd` 知道自己在哪、`uptime` 知道机器累不累、`ls` 知道现场长什么样。这套动作生产上叫"摸底"，写成习惯，能挡掉一大批"在错误的机器上执行正确的命令"的事故——**先认清现场，再谈动手。**

## 2.4 精读 uname -a：这台机器的身份证

第 1 章我们瞥过它，现在逐字段精读——这是全书你第一次"完整解剖一条命令的输出"，解剖方法比结论重要。

```bash
uname -a
```

```text
Linux book 6.18.0-instabox #1 SMP PREEMPT_DYNAMIC Debian 6.18.0-instabox (2025-12-01) x86_64 x86_64 x86_64 GNU/Linux
```

（内核小版本号与编译时间以你的机器为准。）

`uname`（UNIX name）打印内核信息，`-a`（all）全字段。按空格切开，一共六段：

| 字段 | 本例 | 解读 |
| --- | --- | --- |
| 内核名 | `Linux` | 内核家族，天经地义 |
| 主机名 | `book` | 和 `hostname` 命令呼应 |
| 内核版本号 | `6.18.0-instabox` | 内核 6.18.x，**尾巴 `-instabox` 是平台定制内核的印记** |
| 版本与编译信息 | `#1 SMP PREEMPT_DYNAMIC Debian ... (2025-12-01)` | 第 1 次编译、支持 SMP（对称多处理，多核）、可抢占内核、编译日期 |
| 机器架构 | `x86_64` | 即 amd64，我们这代云电脑的主流架构 |
| 处理器特性 / 硬件平台 | `x86_64 x86_64` | 与机器架构一致，常见形态，不必深究 |
| 操作系统 | `GNU/Linux` | GNU 工具链 + Linux 内核，即广义的"Linux 系统" |

重点在第三段：**`-instabox` 后缀**。拿到任何一台生产机器，`uname -a` 的第一动作也是找这种"非标准尾巴"——它告诉你内核被厂商定制过，意味着有厂商特有的参数、虚拟化补丁或硬件驱动。本例它揭示的事实是：这台机器跑在 Firecracker microVM 上（第 1 章讲过），内核是为"海量小虚拟机"裁剪的。**"你连的到底是一台什么系统"——排障第一问，答案半在这条命令里，半在 `cat /etc/os-release`（看发行版是 Debian 13 trixie，第 10 章细读）里。**

## 2.5 正确地离开：退出、断开、暂停、删除

离开的方式有四种，性质完全不同——搞混它们是初学者交学费最多的地方。

**退出会话（logout）**：在提示符下敲：

```bash
exit
```

或者按 `Ctrl-D`（按住 Ctrl 再按 D）——它向 shell 发送"输入结束"信号，效果等同 `exit`。你会看到类似 `Connection to book closed.` 的字样，终端退回你本地的提示符。**机器本身还在云上跑着，还在计费**——很多人以为"退出就是关机了"，于是机器在云端白白跑一夜。

**断开连接（不辞而别）**：直接关掉终端窗口、合上笔记本、断网——效果同样是连接断开、机器照跑。适合"我马上回来"；不适合"我今天不练了"。

**暂停机器（suspend）**：在第 1 章学过，注意它**不在 book 里面执行**，而是在你本地终端里执行：

```bash
instabox suspend book
```

文件、内存、进程现场全保留，只算存储费。恢复用 `instabox resume book`，通常秒级回到现场。**这才是"今天练完了"的标准姿势。**

一张表把四态钉死：

| 动作 | 在哪执行 | 连接 | 机器 | 现场 | 计费 |
| --- | --- | --- | --- | --- | --- |
| `exit` / `Ctrl-D` | book 里面 | 断开 | 继续运行 | 保留 | 继续计 |
| 关终端窗口 | 本地 | 断开 | 继续运行 | 保留 | 继续计 |
| `instabox suspend book` | 本地终端 | 断开 | 暂停 | 保留 | 只算存储 |
| 删除（下一节） | 本地终端/控制台 | 断开 | 没了 | 没了 | 停止 |

## 2.6 删除：唯一不可逆的操作，以及防手滑的姿势

唯一会让数据真没了的是删除。它不可逆、没有回收站、没有"恢复删除"——删掉的是整机：系统盘、持久盘、你的练习文件、`/data/home` 里的一切。所以本书给它配一个警告块，以后每次你要敲删除类命令，都该想起这段话。

> **警告**：删除机器是本章唯一**不可逆**的操作。删之前必须三问：一，`/data/home` 里有没有还需要的东西（`ls /data/home` 看一遍，必要时先备份到本地，第 16 章讲正规备份）；二，这个进度要不要先做个快照（`instabox snapshot save book --name 进度名`，给自己留条后悔药）；三，我删的是 `book` 还是别的机器（命令里的名字瞪大眼睛看三遍）。**安全替代做法：先 `instabox suspend book`，放一星期——确认真的不用了，再删。** 另外，网页控制台的删除入口通常带二次确认弹窗，防手滑比命令行多一道关；命令行删除的确切子命令名与参数，以你机器上 `instabox --help` 的当前输出为准（常见形态为 `instabox delete` 加机器名），别照抄过期教程。生产上这类操作要走变更审批 + 备份验证，一个人、一条命令、一次回车，删掉的就是生产数据。

**删除的正确姿势**：确认不用了再删，别手滑。日常"不用了"的标准动作是 suspend，不是 delete——delete 是"这台机器在我的人生规划里不存在了"时才用的。用第 0 章的账算一下：一台机器每月也就那么点银子，一个误操作的下午值钱得多。

> **生产 vs 实验室**：实验室里删机器，损失是"二十分钟重建 + 一点心情"；生产上删机器，损失是事故报告、复盘会、季度奖。但两者的**安全习惯完全通用**：删前三问、先备份再动手、危险操作走确认流程。在云电脑上把这些习惯练成反射，是你和"口头上的严谨"之间的差距。

## 2.7 `/data/home` 与系统盘：数据到底放哪

现在解释 2.2 节埋的伏笔：root 的家目录 `/root` 在系统盘上，而我们要你把练习文件放 `/data/home` 下。为什么？先看这台机器的双盘结构：

```bash
df -h
```

```text
Filesystem      Size  Used Avail Use% Mounted on
/dev/vda1        16G  2.1G   14G  13% /
/dev/vdb        20G   28K   20G   1% /data
```

（设备名以你的机器为准， virtio 磁盘通常呈现为 `/dev/vdX` 形态。）

| 挂载点 | 角色 | 命运 |
| --- | --- | --- |
| `/`（16 GiB，ext4） | **系统盘**：系统、软件、配置、`/root` 家目录 | 机器**重建即失**——删了重开，一切归零 |
| `/data`（20 GiB） | **持久盘**：专门存你的数据 | 跟着你的账号走，删机器时**理论上是保留的整体**（配合备份才是真保险，见第 16 章《防火墙与数据备份》） |

为什么 `/root` 会是个坑：它是 root 的家目录，默认位置、顺理成章、你随手写的文件都往那掉——但它躺在 16 GiB 的系统盘上。哪天你删了机器重建，或在实验里把系统搞崩重开，`/root` 里的"随手一写"全部蒸发。而 `/data` 是平台专门给你的数据盘，家目录的正确位置在 `/data/home`（普通用户登录后会在各自的 `/data/home/<用户名>` 下落脚，详见第 6 章《用户、群组与权限》）。

所以本书立下第一条铁律：**你的练习文件、笔记、脚本、日志，全部从 `/data/home` 开始。** 动手感受一下，在 `book` 里执行：

```bash
mkdir -p /data/home/notes                  # -p 允许多层目录一次建好（详见第 5 章《文件与目录操作》）
echo "我的第一个文件" > /data/home/notes/day2.txt   # 把一句话写进文件
ls -l /data/home/notes                     # 亲眼确认它躺在这里
```

看到自己创建的文件，Linux 对你就不再是黑箱了。`>` 是重定向写入（会先清空目标文件！），`echo` 是原样输出——两者的详细规矩见第 3、4 章，现在先用起来。

> **SRE 贴士**：分清"系统层"和"数据层"是贯穿全书的思维。 `/data` 对家庭学习是持久盘，对生产就是 NFS/共享存储（数据不随机器消亡），对容器就是挂载的 volume（容器层重建，数据不重建）。**把"易失的"和"该留的"分层，是每一个"删库跑路"事故和"从容重建"神话之间的分界线。**

## 2.8 云电脑使用三条铁律

把第 1 章的坑和第 3 章的知识，压缩成你能背下来的三条：

**铁律一：数据放持久盘。** 一切从 `/data/home` 开始写；重要的还要定期"走出去"（拉回本地、传 GitHub，详见第 16 章《防火墙与数据备份》）——持久盘是平台级的信任，备份才是你自己的。

**铁律二：长任务丢后台。** 任何可能跑过几分钟的任务，别用 `instabox exec book -- ...` 那条路（单条上限 10 分钟，超时退出码 124，输出还不流式），进交互终端后用 `nohup 命令 > 日志 &` 丢后台，让它脱离终端、落盘日志；更讲究的做法是 tmux 会话（详见第 9 章《进程管理与系统监控》）。**任务与终端解耦、输出与文件绑定**——这句话值得抄下来。

**铁律三：单文件别超 10 MiB。** 传文件前 `ls -lh` 看一眼大小，超了就 `split` 分卷传、拼回来（详见第 5 章《文件与目录操作》），或者用 `git`、包管理器让云端自己拉。别和平台限额赌气，那是设计，不是刁难。

## 2.9 终端里的复制粘贴：`Ctrl-Shift-C` 与 `Ctrl-Shift-V`

这条专门写给"从 Windows 世界来的你"，因为踩中率极高：

在 SSH 终端窗口里，**`Ctrl-C` 不是复制，是"中断当前命令"**（这是 Unix 的老规矩，`Ctrl-C` 发送 SIGINT 信号让前台命令立即停摆）。你若按 Windows 习惯用它复制，轻则复制不成，重则把正在跑的 `ping`、`tail -f` 一刀砍了，还得从头再来。正确姿势：

| 操作 | 快捷键 | 说明 |
| --- | --- | --- |
| 复制 | `Ctrl-Shift-C` | 先用鼠标左键划选目标文本，再按组合键 |
| 粘贴 | `Ctrl-Shift-V` | 在提示符处按下，粘贴剪贴板里的命令 |

注意这两个组合都要**加 Shift**，正是为了避开单按 Ctrl-C/Ctrl-V 在终端里的古早语义。另外两个锦囊：一是 Linux 桌面下 SSH 终端常支持"选中即复制、单击中键（滚轮键）粘贴"，macOS 的 Terminal/iTerm 用户用 `Cmd-C`/`Cmd-V`（需要勾选"将选中的文本复制到剪贴板"类选项）。二是从网页、文档复制命令粘进终端时要多个心眼——网页复制的"引号"可能是中文引号，粘贴进去必报错；本书的命令请照着手打两遍，比复制粘贴学得快。

## 2.10 换个姿势看云电脑：Desktop 桌面 + Chromium

本书默认你在黑漆漆的终端里工作，但平台还藏了一扇窗：网页控制台里的 Desktop（远程桌面）入口。输入平台密码或点 "Connect"，你会看到云电脑的**图形桌面**——有任务栏、有文件管理器，还预装了 Chromium 浏览器，地址栏输入什么都能打开。

这个桌面能干嘛？三个正经用途：一，"看一眼"云电脑——第 1 章说过它是默认模板 `agent-browser` 的招牌能力，用来验证"我的机器确实有 GUI 能力"；二，图形化排障——某个服务要看日志、要试图形客户端时，比敲命令直观；三，卷 4/卷 6 的浏览器自动化、内网测试页面，直接在桌面里打开。至于传文件、改配置、跑服务——**这些在 SSH 里干更快。**

> **SRE 贴士**：真实生产的服务器，九成九**没有桌面**——容器镜像连编辑器都不带，服务器 SSH 是唯一入口。本书故意以终端为主，就是为了让你练"没有 GUI 也活得很好"的硬功夫；Desktop 留给"看一眼、试一试"，别让它变成依赖。判断一个运维候选人熟不熟练，问他"没桌面的机器你怎么装个软件"比问他"会不会用远程桌面"有用得多。

## 本章小结

这一章完成了从"拥有机器"到"驾驶机器"的跨越，四件事：

1. **连接**：`instabox ssh book` 一条命令经平台通道登录；首次连接的指纹确认要看清 `yes/no/[fingerprint]`，指纹即身份的生产意识从今天埋下。
2. **提示符**：`root@book:~#` 六段式（用户 root、主机名 book、当前目录 `~`=`/root`、`#`=root 身份，`$`=普通用户），以及"提示符不算命令的一部分"。
3. **第一组命令**：`whoami`/`id`/`pwd`/`ls`/`hostname`/`uptime` 六兄弟各司其职，`uname -a` 六段解剖确认"这是什么系统"；`exit`/`Ctrl-D` 退出，且退出≠关机≠暂停。
4. **纪律**：`/data/home` 持久盘 vs 16 GiB 系统盘的分工、三条铁律（数据放持久盘、长任务丢后台、单文件别超 10 MiB）、`Ctrl-Shift-C/V` 的复制粘贴规矩、删除前三问。

下一章起，我们开始系统地练命令：Shell 是什么、命令的通用格式、以及 Linux 的文件系统树——所有命令的舞台。

## 动手练习

以下题目都在 `book` 云电脑上完成，文件一律放 `/data/home`。

1. `instabox ssh book` 建立连接，把首次连接的指纹确认原文抄进笔记；进入后依次执行 `whoami`、`id`、`pwd`、`ls`、`hostname`、`uptime`，把每条输出贴进笔记并各写一句判读。
2. 在 `book` 里执行 `mkdir -p /data/home/notes`、`echo "第二条铁律：长任务丢后台" > /data/home/notes/day2.txt`，然后 `exit` 退出、重新 `instabox ssh book`、`cat` 一下那个文件，确认它还在（`cat` 的用法见第 4 章《命令行入门与文件系统树》，不会就先用 `ls` 确认它在）。
3. 分别用 `exit` 和 `Ctrl-D` 各退出一次，观察两种方式的提示符变化与断开信息有何异同。
4. 在终端里练习复制粘贴：鼠标划选 `hostname` 的输出，`Ctrl-Shift-C` 复制，在新提示符处 `Ctrl-Shift-V` 粘贴；再故意按一次 `Ctrl-C`，记录它对你当前命令做了什么（提示：可以先跑个 `sleep 60` 当靶子）。
5. 打开网页控制台的 Desktop 入口，看一眼云电脑桌面和 Chromium；比较"SSH 终端"与"远程桌面"两种方式，写下你各自会在什么场景用它们。
6. 综合题：模拟一次完整的"收工 + 防丢"流程——`ls /data/home` 盘点今天产物、给今天的进度建个快照（`instabox snapshot save book --name after-ch02`）、本地终端 `instabox suspend book`、再 `instabox resume book` 验证现场、最后写下你的"删除前三问"清单。

> **参考答案**：
>
> 1. 指纹确认原文应有 `The authenticity of host ... can't be established.` 与 `Are you sure you want to continue connecting (yes/no/[fingerprint])?` 两段关键行；判读示例：`id` 显示 `uid=0(root)`，所以我确实是以管理员身份登录。
> 2. 文件在 `/data/home/notes/day2.txt`，重连后仍在——证明持久盘跨会话保留；若不见了，检查是否误写到了 `/root`（系统盘）下。
> 3. `exit` 显示 `logout` 类信息后主动断开；`Ctrl-D` 不打印 logout 直接断开；两者 Machines 状态不变，机器继续运行。
> 4. `Ctrl-Shift-C/V` 完成"鼠标划选 + 组合键"复制粘贴；`Ctrl-C` 会让 `sleep 60` 立即终止并回到提示符——证明它在终端里是中断信号，不是复制。
> 5. 结论示例：日常操作、写脚本、跑服务用 SSH；看图形界面、试浏览器场景、临时验证用 Desktop；生产服务器通常只有前者。
> 6. 流程要点：`ls /data/home` → `instabox snapshot save book --name after-ch02` → `instabox suspend book` → `instabox resume book` → `instabox ssh book` 验证现场；删除前三问：`/data/home` 有没有还要的东西 / 进度要不要做快照 / 命令里的机器名瞪眼再看三遍。
